## 3. 补课：前面几课你需要知道的东西

### 3.1 仿真平台：gym-pybullet-drones（第 1 课起）

整个课程在 [gym-pybullet-drones](https://github.com/utiasDSL/gym-pybullet-drones) 里仿真 Crazyflie 2.x
（一架约 27 克的开源小四旋翼）。本课用到的部分：

- **`CtrlAviary`**：最基础的环境，你直接给 4 个电机的转速（RPM），它推进物理仿真。
  - `drone_model=DroneModel.CF2X`：Crazyflie 2.x，X 型布局。
  - `pyb_freq=240`：物理引擎每秒算 240 步；`ctrl_freq=48`：控制频率 48 Hz。
    所以每调用一次 `env.step()`，内部跑 240/48 = **5 个物理步**，时间前进 1/48 秒（约 20.8 ms）。
    本课所有"步"（step）指的都是这个 **48 Hz 的控制步**。
  - `env.reset(seed=...)` 返回 `obs`，`obs[0]` 是 0 号无人机的 **20 维状态向量**：
    `[0:3]` 位置 x,y,z；`[3:7]` 四元数姿态；`[7:10]` 横滚/俯仰/偏航角；`[10:13]` 线速度；
    `[13:16]` 角速度；`[16:20]` 上一次的电机指令。本课只用到 `state[0:3]`（位置）和 `state[1]`（y 坐标）。
  - `env._getDroneImages(0)`：从无人机机载相机渲染一张图（RGB、深度、分割）。相机朝机头方向（+x），
    **视场角（FOV）60°**，分辨率由 `env.IMG_RES` 决定，本课设成 64×64。
- **坐标系约定**：无人机从 `(0, 0, 1)` 出发，向 **+x** 方向飞，终点线在 x = 3.0 m。
  **+y 是左边，−y 是右边**。偏航角始终保持 0，所以机体坐标系和世界坐标系是同一个。
- **柱子是"纯视觉体"**：用 `p.createVisualShape` + `p.createMultiBody(baseMass=0)` 创建，只有外观、没有碰撞体积。
  无人机会直接"穿过去"，所以"撞没撞"不是物理碰撞，而是**算出来的**：水平距离（只看 x、y）小于 `COLLISION_R = 0.22 m`
  就算坠机。这样做的好处是：即使穿过柱子，仿真也继续，距离标签始终干净可算。

### 3.2 两层控制结构：AI 只发速度，PID 负责飞稳（第 1 课）

无人机控制分两层：

1. **上层（AI / 规划器）**：只决定"往哪个方向、多快"，即速度指令 `(vx, vy, vz, yaw_rate)`。
2. **下层（飞控）**：`DSLPIDControl` 是 gym-pybullet-drones 自带的 PID 控制器，输入"目标位置 + 目标速度 + 当前状态"，
   输出 4 个电机转速，负责姿态稳定。

本课的 `VelCommander`（见第 5 节）就是两层之间的转接器：把速度指令积分成一个不断前移的参考点，让 PID 去追。

### 3.3 第 3 课：TinyDronet（`train_cnn.py`）

第 3 课训练了一个仿 PULP-Dronet 的小卷积网络，输入 64×64 图片，输出障碍物的方位角（模仿第 2 课手写的颜色检测器）。
结构：

```
输入 (3, 64, 64)
Conv 5×5, 16 通道, stride 2 → ReLU   →  (16, 32, 32)
Conv 3×3, 32 通道, stride 2 → ReLU   →  (32, 16, 16)
Conv 3×3, 64 通道, stride 2 → ReLU   →  (64, 8, 8)
AdaptiveAvgPool2d(1) 全局平均池化     →  (64, 1, 1)
Flatten → Linear 64→32 → ReLU → Linear 32→1   (方位角)
```

**本课只复用它的卷积部分**（`self.features` 去掉最后的全局池化层），不加载第 3 课训练好的权重——
世界模型的编码器是从头训练的。`train_cnn.py` 里的 `main()` 和数据路径本课用不到，保留只是为了让 `TinyDronet` 能被 import。

### 3.4 第 4 课 / 第 14b 课：GAP8 和 512 KB 预算

真机上的 AI 跑在 Crazyflie 的扩展板 AI-deck 上，芯片是 **GAP8**。它的 L2 内存只有 **512 KB**，
所以课程的"北极星"约束是：**模型量化成 int8 后（每个参数 1 字节），连同运行时的中间激活一起要塞进 512 KB**。
第 4 课把 TinyDronet 量化成 int8 只有 25.8 KB。本课的世界模型约 81 KB，总预算约 137 KB，见第 9 节的详细计算。

### 3.5 第 17 课：单目深度；第 19 课：强化学习避障

- **第 17 课**训练了从单张图片估计深度的网络，是"反应式"的：只回答"现在离多近"。
- **第 19 课**用 **PPO**（stable-baselines3）训练无人机穿过每回合位置随机的多根柱子。它的奖励函数是：
  `奖励 = 25 × 本步前进距离 − 0.02`，撞柱 `−30` 并结束，到终点 `+50` 并结束。
  本课第 6 步原样沿用了这个奖励形状。

### 3.6 第 20 课：域随机化（`randomize.py`）

"域随机化"（Domain Randomization）是在训练时故意加入各种外观变化，逼模型去认形状而不是死记像素颜色，
这样换到真实相机时不至于失灵。`randomize.py` 只有两个函数，输入都是 `[0,1]` 范围的 float 图像数组 `(N,H,W,3)`：

- `jitter(imgs, rng)`：**训练用**。每张图随机乘一个亮度系数 0.5–1.5，再加标准差 0–0.18 的高斯噪声，最后截断到 [0,1]。
- `shift_appearance(imgs, brightness=0.7, noise=0.15, seed=7)`：**测试用**。一个**固定的**偏移：整体变暗到 70%，
  加标准差 0.15 的噪声。它代表"一台模型从没见过的相机"，用来模拟 sim-to-real 差距。

### 3.7 几个机器学习概念（后面会反复出现）

- **隐向量 / 隐空间（latent / embedding）**：编码器把一张图压缩成一个短向量（本课 64 维），叫 `z`。
  "在隐空间预测"就是预测未来的 `z`，而不是未来的像素。
- **BCE（二元交叉熵）**：训练"是/否"概率的标准损失。代码里用 `BCEWithLogitsLoss`，网络输出 logit，过 sigmoid 才是概率。
- **AUC**：衡量一个打分器把正样本排在负样本前面的能力。0.5 = 随机瞎猜，1.0 = 完美。只看排序，不看阈值。
- **EMA（指数滑动平均）**：`target = 0.99 × target + 0.01 × online`，让一个"目标网络"缓慢跟随在线网络。
- **PPO**：一种常用的策略梯度强化学习算法。stable-baselines3 提供现成实现；sb3-contrib 的 `RecurrentPPO` 是带 LSTM 记忆的版本。

## 4. 核心思想：为什么要世界模型，为什么在隐空间预测

### 4.1 反应式的问题

到第 28 课为止，所有模型都是**反应式**的：深度网络、RL 策略回答的都是"对**现在**已经很近的障碍，我该怎么办？"
但在高速下，"现在"已经太晚了：等柱子塞满画面，一架加速度有上限的 27 克无人机根本来不及转。

**世界模型**补上的是**预判**：它学会"世界会怎么变，而且会**因为我做的动作**怎么变"，于是无人机可以对
**即将**发生的事提前行动。

### 4.2 为什么不预测像素（V-JEPA 路线）

最直觉的做法是"预测下一帧图像"（像素生成 / 扩散模型）。问题是：慢，而且会凭空生成控制器根本用不上的细节。
本课走的是 Meta 的 **V-JEPA** 路线：**预测未来的隐向量（embedding），而不是未来的像素**。
没有幻觉画面、没有扩散延迟、算力固定。

真正的 V-JEPA 是十亿参数级的 ViT，要 Orin 级 GPU，塞不进 GAP8。所以本课是它的 **nano 蒸馏版**：
同样的"联合嵌入预测"原理，缩到 512 KB int8 预算之内。

### 4.3 四个小网络

```
          图像 x_t (3×64×64)
                │
        ┌───────▼────────┐
        │ Encoder  f_θ   │  图像 → 64 维隐向量 z_t
        └───────┬────────┘
                │ z_t ─────────────────────────────┐
                │                                  ▼
  候选动作 a ──►┌────────────────┐         ┌───────────────┐
                │ Predictor g_φ  │         │ DangerNowHead │ → P(现在就太近)   ← 反应式信号
                └───────┬────────┘         └───────────────┘
                        │ ẑ_{t+k}，k ∈ {4, 8, 16, 32} 步
                ┌───────▼────────┐
                │ CollisionHeads │ → 每个 k：P(k 步内进入 0.7 m 警戒环)、P(k 步内进入 0.35 m 临界环)
                └────────────────┘                                        ← 预判式信号
```

- **Encoder**：复用 TinyDronet 卷积层，但把全局平均池化换成 **4 条竖直条带池化**（左→右 4 个区域），保留"障碍物在左边还是右边"的信息。
- **Predictor**：输入 `(z_t, 动作)`，同时输出 4 个时间尺度的未来隐向量：4/8/16/32 步，在 48 Hz 下约为 **83 / 167 / 333 / 667 ms**。
- **Collision heads**：从预测的未来隐向量判断"k 步之内会不会太靠近柱子"，两个距离环各一个输出。
- **Danger-now head**：只看当前 `z_t`，判断"现在是不是已经太近"。这是**反应式基线**，故意保留下来作为对照：
  预判必须在**同一个传感器、同一个编码器**的条件下打败它，比较才公平。

为什么要两个环（0.7 m 和 0.35 m）？只有一个 0.7 m 的环时，一旦无人机已经进入环内，**所有**动作的"警戒"概率都是 1
（绕过柱子本来就会短暂进入 0.7 m，这个预测是对的），规划器就分不出哪个动作好了。实测结果是无人机在边界上僵住、永久悬停。
0.35 m 临界环能区分"擦身而过"和"真的要撞"。

### 4.4 一个贯穿全课的教训

原作者第一版模型的碰撞 AUC 有 0.9，但"往左躲还是往右躲"的排序和随机猜一样。**AUC 衡量的是"距离判断"，规划需要的是"在几个动作里做选择"。**
为了把"选择"修好，依次加了：干预片段（第 5 节）、反事实标签、视场角遮罩，最后是方位感知池化（根因）。
所以本课专门有一个 **veer-ranking（转向排序）** 指标来测"选择"能力。

## 5. 第 1 步 `gen_wm_dataset.py`：自己生成"干预式"数据集

这个文件有两个身份：(1) 生成数据集的脚本；(2) **全课的公共库**，定义了常量、动作、环境、控制器、柱子生成函数，
其它所有文件都从这里 import。

### 5.1 常量

| 常量 | 值 | 含义 |
|---|---|---|
| `IMG_RES` | 64 | 相机分辨率和网络输入尺寸 64×64 |
| `HORIZONS` | (4, 8, 16, 32) | 预测时域，单位：控制步（≈ 83/167/333/667 ms） |
| `H_MAX` | 32 | 最长时域 |
| `DANGER_R` | 0.7 m | 警戒环："很快就会危险" |
| `CRIT_R` | 0.35 m | 临界环："马上要撞" |
| `RADII` | (0.7, 0.35) | 两个环，顺序固定：索引 0 = 警戒，1 = 临界 |
| `COLLISION_R` | 0.22 m | 小于这个水平距离就算坠机（与第 3、19 课一致） |
| `CTRL_HZ` | 48 | 控制频率 |
| `FOV_HALF_DEG` | 28° | 判断"柱子在不在视野内"用的半视场角。相机实际是 60°（半角 30°），留了 2° 余量 |
| `START` | (0, 0, 1) | 起点，离地 1 m |

### 5.2 六个高层指令 `ACTIONS`

每个指令是 `(vx, vy, vz, yaw_rate)`，单位 m/s，这是速度倍率为 1 时的"基础速度"：

| 名字 | vx | vy | vz | 说明 |
|---|---|---|---|---|
| `forward` | 0.80 | 0 | 0 | 直飞 |
| `slow` | 0.30 | 0 | 0 | 慢速直飞 |
| `veer_left` | 0.50 | +0.50 | 0 | 向左前方斜飞 |
| `veer_right` | 0.50 | −0.50 | 0 | 向右前方斜飞 |
| `climb` | 0.40 | 0 | +0.40 | 边前进边爬升 |
| `hover` | 0 | 0 | 0 | 悬停 |

- `ACTION_NAMES` 是名字列表，`ACTION_VECS` 是 6×4 数组，`FORWARD = 0` 是 `forward` 的索引。
- yaw_rate 始终为 0，所以机头一直朝 +x，机体系 = 世界系。这让数据集里的动作和后面规划器的候选动作**完全是同一组数**。

**速度倍率 `SPEED_RANGE = (0.75, 2.0)`**：每条 rollout 随机抽一个倍率，把整组指令一起乘上去。
`forward` 因此在 0.6–1.6 m/s 之间。这样模型能见到"同一条走廊被慢飞和快飞"的情况，学到"危险程度取决于速度"，
这是第 4c 步的物理基础。

**动作归一化 `A_NORM`**：每一维取所有动作的最大绝对值 × 2.0（最大倍率），即
`(1.6, 1.0, 0.8, 1e-6)`。喂给网络前动作都除以它，使每一维落在约 [−1, 1]。yaw 维是 0，用 1e-6 防止除以 0。

### 5.3 `make_env(gui=False)`

创建 `CtrlAviary`：CF2X、1 架、起点 START、PyBullet 物理、240 Hz 物理 / 48 Hz 控制，并把 `env.IMG_RES` 改成 64×64。
`gui=True` 会打开 PyBullet 窗口（需要图形界面；WSL 下需要 WSLg）。第 1、3（指闭环）、4、6 步都用它。

### 5.4 `make_ctrl()`

返回一个 `DSLPIDControl(drone_model=CF2X)`，就是下层 PID 飞控。

### 5.5 `spawn_pillars(env, rng, in_path, solo=False, randomize=False)`

在**刚 reset 过的**场景里放 2–3 根柱子，返回它们的水平中心坐标列表 `[(x, y), ...]`。

- `in_path=True`：第 1 根柱子放在航道正前方：x ∈ [1.3, 2.0]，y ∈ [−0.2, 0.2]。这是"有威胁"的航道。
- 其余柱子（或 `in_path=False` 时全部）放在两侧：x ∈ [0.9, 2.6]，|y| ∈ [0.9, 1.5]，左右随机。
  这些侧柱相对无人机的方位角大约 60–90°，**在相机视野之外**。
- `solo=True`：只放正前方那 1 根（第 4c 步速度扫描用，保证威胁双方都看得见）。
- `randomize=True`：柱子半径 0.14–0.22、高 1.0–1.8、颜色在基础橙红色上随机 ±0.3（第 5 步用）。
  否则固定：半径 0.18、高 1.4、橙红色 `[0.80, 0.32, 0.22]`。
  注意：半径一变，"看起来多大"就不再能准确反映"有多远"，对单目视觉来说更难，也更真实。
- 柱子只是视觉体；下一次 `env.reset()` 会把它们清掉。

### 5.6 `VelCommander`：速度指令 → 电机转速

```python
cmd = VelCommander(make_ctrl(), env.CTRL_TIMESTEP)   # dt = 1/48 s
cmd.reset(START)
rpm = cmd.rpm(state, v_cmd)                           # 每个控制步调用一次
```

内部逻辑：维护一个**参考位置** `ref`。每步 `ref += v × dt`，然后让 PID 去追 `target_pos=ref, target_vel=v`。
**指令一变**（与上次不同），就把 `ref` 重新对齐到无人机当前位置，避免参考点和实际位置差太远导致猛冲。
这样 AI 层只需要输出速度，48 Hz 的姿态控制仍是 PID 的事。

### 5.7 其它小工具

- `grab_frame(env)`：拍一张 64×64×3 的 uint8 RGB 图。
- `nearest_planar(pos_xy, pillars)`：到最近柱子中心的水平距离；没有柱子时返回 9.0。

### 5.8 `_schedule(rng, length, passive)`：每条 rollout 的指令时间表

返回两个长度为 `length` 的数组：每步的动作 id、每步所属的片段 id。

- 前 24–48 步全部是 `forward`（接近阶段），片段 id = 0。
- 之后是一串**保持片段（held segments）**：每段随机抽 6 个指令之一，**持续 40–56 步（约 1 秒）**，片段 id 依次为 1, 2, 3, …
- `passive=True`：全程 `forward`，片段 id 全是 0（被动录像，相当于单纯直飞穿过航道）。

**为什么指令要"保持"？** 世界模型要回答"如果我**继续这样做** k 步会怎样"，就需要训练样本里真的有"同一个动作保持了 k 步"的片段。
每次片段切换，又提供了一次"同样的画面、不同的指令、不同的结果"的对比，这正是规划器需要的"以动作为条件"的能力。
片段长度至少 40 步，比最长时域 32 步长，所以一个片段里一定有完整的 32 步窗口。

### 5.9 `gen(n_rollouts, length, seed=0, randomize=False)`：主循环

对每条 rollout `r`：

1. `env.reset()`、`cmd.reset(START)`：每条都是**全新试验**，无人机回到起点，PID 积分清零。
   （原作者第一版的 bug 就是没重置，变成一次长长的漂移飞行；`--selftest` 专门检查这一点。）
2. `in_path = (r % 2 == 0)`：偶数条有正前方的柱子，奇数条没有。
3. 随机速度倍率 `speed[r]`。
4. 放柱子，生成时间表；`passive = (r % 3 == 2)`，即每 3 条中有 1 条是全程直飞。
5. 逐步飞行（每步）：
   - 拍照存 `frames`，存位置 `pos`，存到最近柱子的距离 `dists`；
   - 记录的动作是**指令本身** `speed × ACTION_VECS[act_id]`（意图），**不是测得的实际速度**。
     因为部署时控制器只能把"指令"喂给模型，所以模型就必须以指令为条件来学；
   - `randomize=True` 时，**实际执行**的指令会延迟 0–2 步（`lat`），并且每步乘上 (1 + N(0, 0.08)) 的噪声，
     但**记录**的仍是干净的意图。模型学"意图 → 结果"，现实在中间晃动，标签来自无人机真正飞到的位置，这正是部署所需的鲁棒性；
   - 用 `VelCommander` 算 RPM，`env.step()`。

返回的字典（保存为 `output/wm_dataset.npz`），R = rollout 数，L = 每条长度：

| 键 | 形状 / 类型 | 含义 |
|---|---|---|
| `frames` | (R, L, 64, 64, 3) uint8 | 每步的相机画面 |
| `actions` | (R, L, 4) float32 | 每步的**指令**（已乘速度倍率，未归一化） |
| `act_id` | (R, L) int16 | 每步的动作 id（0–5） |
| `seg` | (R, L) int16 | 每步所属的保持片段 id（0 = 接近段/被动） |
| `dists` | (R, L) float32 | 每步到最近柱子的水平距离 |
| `pos` | (R, L, 3) float32 | 每步无人机位置 |
| `pillars` | (R, 3, 2) float32 | 柱子中心，不足 3 根的用 NaN 填充 |
| `in_path` | (R,) bool | 是否有正前方柱子 |
| `speed` | (R,) float32 | 速度倍率 |
| `randomized` 等 | 标量 | 元信息 |

> **柱子位置只用于生成标签和评分，从不用于控制。** 这是贯穿全课的规则。

内存提示：64 条 × 120 步的画面约 94 MB，没有问题。

### 5.10 `window_valid(seg_row, t, k)`

当 `t+k` 仍在这条 rollout 内，且 `t` 和 `t+k` 在**同一个保持片段**里时返回 True，即"这 k 步里指令确实没变"。
只有这样的窗口才能用来训练"保持动作 a 走 k 步后会怎样"。

### 5.11 `counterfactual_labels(data)`：反事实标签（关键）

真实飞过的 rollout 只告诉模型"**实际执行的那个动作**发生了什么"。但规划器问的是"**六个选项里哪个最安全**"。
仿真器知道所有柱子的位置，可以免费回答"**如果**当时做的是别的动作，会怎样"：

对每一帧 `t` × 每个候选动作 `i` × 每个时域 `k` × 每个环：
从该帧位置出发，按动作 `i` 的速度**直线外推** k 步，算出这段路径上离任何柱子的最近距离，小于环半径就标 1。

返回两个数组：

- `labels`：uint8，形状 (R, L, 6, 4, 2)，即 (rollout, 步, 动作, 时域, 环)。
- `visible`：uint8，形状 (R, L, 6)。如果某个动作的警戒标签是正的，**但造成威胁的那根柱子不在相机视场内**
  （与 +x 方向夹角超过 28°），就标 0，表示"这个标签单看这一帧回答不了"。训练时这些样本不算损失。
  道理很简单：单帧模型不可能知道身旁或身后的柱子，硬训只会教它噪声。（根本解法是记忆或转动机头，见第 6 步。）

诚实说明：这是**直线运动学**近似，没有 PID 的过渡过程；但这个误差对所有候选动作是对称的，所以动作之间的**排序**仍然可信。
而且它之所以存在，是因为仿真标签本来就是"特权信息"；换成真实数据，就只能用实际执行动作的监督，需要多得多的数据。

**这个函数在每一帧都有效**（不需要知道真实飞过的未来），所以它把"以动作为条件"的监督从少数片段切换点扩展到了每一帧。

### 5.12 `as_pairs(data, k)`

把序列数据切成单一时域 k 的 `(当前帧, k 步后的帧, 归一化动作, 是否危险)` 样本，只保留指令确实保持了 k 步的窗口。
本文件只在 `main()` 里用它统计每个时域的样本数和正样本比例。

### 5.13 命令行

```bash
python src/gen_wm_dataset.py --rollouts 64        # 原作者推荐 64 条；默认 32 条 × 120 步
python src/gen_wm_dataset.py --randomize          # 第 5 步用的随机化数据集（注意会覆盖同名文件，见第 13 节）
python src/gen_wm_dataset.py --selftest           # 10 条 × 100 步，并检查一系列断言
```

成功时打印 `WM-DATA OK: ...`，包括每个时域的样本数 `n` 和正样本比例 `pos`。

## 6. 第 2 步 `train_world_model.py`：训练 nano 世界模型

### 6.1 先看全貌：这个模型到底回答什么问题

一句话：**给它一张当前的相机画面，再告诉它"我打算做什么动作"，它回答"如果照这样一直做下去，
0.08 秒、0.17 秒、0.33 秒、0.67 秒之后，我会不会离柱子太近"。**

| | 内容 |
|---|---|
| 输入 1 | 当前画面，64×64 的 RGB 图 |
| 输入 2 | 一个打算执行的动作，4 个数 `(vx, vy, vz, yaw_rate)`，例如 `veer_left` |
| 输出 | 一张 4×2 的概率表：4 个未来时刻 × 2 个距离环 |

输出表长这样（数字是举例）：

| 未来时刻 | P(进入 0.7 m 警戒环) | P(进入 0.35 m 临界环) |
|---|---|---|
| 4 步后（≈ 83 ms） | 0.05 | 0.01 |
| 8 步后（≈ 167 ms） | 0.12 | 0.02 |
| 16 步后（≈ 333 ms） | 0.55 | 0.10 |
| 32 步后（≈ 667 ms） | 0.93 | 0.61 |

意思是："照这个动作飞，0.3 秒内还算安全，但 0.67 秒内大概率会撞上。"

**同一张画面，可以换不同的动作反复问。**第 4 步的规划器就是这样用的：拿当前画面，把 5 个候选动作各问一遍，
得到 5 张这样的表，然后比较哪个动作最安全。所以"动作"是输入，这是这个模型被称为**世界模型**的原因：
它预测的是"世界会**因为我的动作**怎么变"。

另外还有一个附带输出：**P(现在就已经离柱子 < 0.7 m)**。它不看动作、不看未来，只看当前画面，是用来对比的"反应式"信号。

### 6.2 网络结构：四个小网络串起来

```
当前画面 x_t
 (3, 64, 64)
     │
     ▼
┌──────────────┐
│ ① Encoder    │   "看图，提炼要点"
└──────────────┘
     │
     ▼
  z_t (64 个数)  ─────────────────────────────┐
     │                                        │
     │      动作 a (4 个数)                     │
     │        │                               ▼
     ▼        ▼                        ┌──────────────────┐
┌─────────────────────┐                │ ④ DangerNowHead  │ → P(现在就太近)    1 个数
│ ② MultiPredictor    │  "脑中快进"      └──────────────────┘
└─────────────────────┘
     │
     ▼
  ẑ_4, ẑ_8, ẑ_16, ẑ_32   (4 个"想象中的未来 z"，每个 64 个数)
     │
     ▼
┌─────────────────────┐
│ ③ CollisionHeads    │  "看想象的未来，判断危不危险"
└─────────────────────┘
     │
     ▼
  4×2 概率表（上面那张）
```

下面逐个讲。

#### ① Encoder：图像 → 64 维向量 z

这部分你已经理解了：把一张图压缩成 64 个数 `z`，`z` 就是这张画面在 latent space 里的"摘要"。
只补充一个细节：最后一步为什么是**分 4 条竖直条带**。

```
卷积层输出的特征图：64 个通道，每个 8×8

    左 ←────────────→ 右
   ┌────┬────┬────┬────┐
   │ 条 │ 条 │ 条 │ 条 │     每条带（8 高 × 2 宽）内部求平均
   │ 带 │ 带 │ 带 │ 带 │     → 每个通道得到 4 个数（左、中左、中右、右）
   │ 1  │ 2  │ 3  │ 4  │     → 64 通道 × 4 = 256 个数
   └────┴────┴────┴────┘     → 一层全连接 256 → 64，得到 z
```

如果像第 3 课那样把整张 8×8 一起平均，就只剩"有没有柱子、多大"，丢掉了"柱子在画面左边还是右边"。
而后面要判断"往左躲还是往右躲"，恰恰需要左右信息。

#### ② MultiPredictor：在脑子里"快进"

这是你说没看懂的部分，重点讲。

**它做什么**：输入"现在的 z"和"一个动作"，输出"如果一直保持这个动作，4 个未来时刻的 z 分别会是什么"。
它不生成未来的**图片**，只生成未来图片的**摘要**（64 个数）。

名字里的 **Multi** 指的是**多个时间尺度（multi-horizon）**：一次同时预测 4 个未来时刻，而不是只预测下一刻。

**内部结构**：

```
z_t (64 个数) ──┐
                ├─► 拼接成 68 个数 ─► 全连接 68→128 ─► ReLU ─► feat (128 个数)   ← "共享主干"
动作 a (4 个数) ─┘                                              │
                                                               │
              ┌──────────────────┬──────────────────┬──────────┴───────┐
              ▼                  ▼                  ▼                  ▼
        全连接 128→64       全连接 128→64       全连接 128→64       全连接 128→64    ← 4 个"小头"
              │                  │                  │                  │
            Δ_4                Δ_8                Δ_16               Δ_32         (各 64 个数：变化量)
              │                  │                  │                  │
        ẑ_4 = z_t + Δ_4    ẑ_8 = z_t + Δ_8    ẑ_16 = z_t + Δ_16  ẑ_32 = z_t + Δ_32
```

对应代码只有几行：

```python
class MultiPredictor(nn.Module):
    def __init__(self, d=64, a=4, h=128, horizons=(4, 8, 16, 32)):
        self.trunk = nn.Sequential(nn.Linear(d + a, h), nn.ReLU())        # 共享主干
        self.heads = nn.ModuleList(nn.Linear(h, d) for _ in horizons)     # 每个时域一个头

    def forward(self, z, a):                     # z: (B, 64)  a: (B, 4)
        feat = self.trunk(torch.cat([z, a], 1))  # (B, 128)
        return torch.stack([z + head(feat) for head in self.heads], 1)  # (B, 4, 64)
```

三个设计要点：

1. **为什么共享主干、分 4 个头**：理解"现在的场景 + 我要做的动作"这件事，对所有时域都一样，所以用同一个主干；
   只有"往前快进多远"不同，所以每个时域一个小头。这样预测 4 个时刻只比预测 1 个多花几 KB 参数。
2. **为什么输出"变化量" Δ，再加回 z_t**：这叫**残差预测**。如果网络什么都没学会（Δ = 0），
   它的预测就是"未来和现在一样"，这本身就是一个还不错的基线。网络只需要学"会变多少"，比从零学"未来是什么"容易得多。
3. **为什么要 4 个时域**：本课要证明的是"能提前反应"。想提前几百毫秒做决定，模型就得看到几百毫秒以后；
   只预测 83 ms 不够。同时近的时域对"马上要撞"更敏感，远的时域对"提前预警"有用，第 4 步的规划器会把它们加权组合。

**一个具体例子**：无人机正对前方 1.5 m 处的柱子。

- 问 `(z_t, forward)`：预测器输出的 ẑ_32 应该接近"柱子塞满画面中央"那种画面的 z。
- 问 `(z_t, veer_left)`：ẑ_32 应该接近"柱子在画面右侧边缘"那种画面的 z。
- 问 `(z_t, veer_right)`：ẑ_32 应该接近"柱子在画面左侧边缘"那种画面的 z。

预测器自己并不知道哪个危险，它只负责"想象未来的画面摘要"。判断危不危险是下一个网络的事。

#### ③ CollisionHeads：看"想象的未来"，判断危险

每个时域一个全连接层 64 → 2：输入该时域的 ẑ，输出 2 个数（过 sigmoid 后就是概率）：
P(到那时为止进入过 0.7 m 环)、P(到那时为止进入过 0.35 m 环)。4 个时域合起来就是那张 4×2 的表。

```python
class CollisionHeads(nn.Module):
    def __init__(self):
        self.heads = nn.ModuleList(nn.Linear(64, 2) for _ in range(4))   # 每个时域一个
    def forward(self, zh):                       # zh: (B, 4, 64)  预测器的输出
        return torch.stack([h(zh[:, i]) for i, h in enumerate(self.heads)], 1)  # (B, 4, 2)
```

为什么要两个环，见第 4.3 节：只有 0.7 m 一个环的话，一旦已经进到环里，所有动作都会报"危险"，就分不出好坏了。

#### ④ DangerNowHead：只看现在

一个全连接层 64 → 1，直接接在 `z_t` 上（不经过预测器、不看动作），输出 P(现在离柱子 < 0.7 m)。
它代表"反应式"做法。保留它，是为了在**同一个编码器**的条件下，公平地比较"预判"和"反应"。

#### 规模

| 网络 | 参数数 |
|---|---|
| ① Encoder | 40,800 |
| ② MultiPredictor | 41,856 |
| ③ CollisionHeads | 520 |
| ④ DangerNowHead | 65 |
| 合计 | 83,241（int8 下约 81.3 KB，远小于 GAP8 的 512 KB） |

### 6.3 训练的核心难题：预测的 z 和谁比？

CollisionHeads 和 DangerNowHead 好训练：仿真器知道真实距离，直接有"危险 / 不危险"的标签。

**难的是 MultiPredictor**：它输出的是"未来的 z"，可 z 是编码器自己发明的摘要，没有人标注过"正确的 z"是多少。那拿什么当答案？

**答案：用真实的未来画面。**数据集里，第 t 帧之后真的飞了 k 步，第 t+k 帧的画面也录下来了。
把第 t+k 帧送进编码器，得到的 z 就是"正确答案"：

```
训练样本：第 t 帧画面、第 t 帧执行的动作 a、第 t+4/8/16/32 帧画面

    预测：  ẑ_k = Predictor( Encoder(第 t 帧), a )
    答案：  z_k = Encoder(第 t+k 帧)
    损失：  ‖ẑ_k − z_k‖²   （越接近越好）
```

**但这样做有个陷阱：塌缩（collapse）。**预测和答案都来自同一个编码器。如果编码器偷懒，把所有图片都编码成同一个向量
（比如全 0），那预测永远等于答案，损失为 0，但什么都没学到。

本课用两个办法防止塌缩：

1. **答案用一个"慢一拍"的编码器副本来算（EMA 目标编码器）。**
   - 代码里有两个结构完全一样的编码器：`enc`（在线编码器，正常训练）和 `tgt`（目标编码器，专门算答案）。
   - `tgt` **不参与梯度更新**。每训练一步后，让它向 `enc` 靠近一点点：
     `tgt 的参数 = 0.99 × tgt 的参数 + 0.01 × enc 的参数`。
   - 效果：答案变化很慢，而且梯度不能直接把"答案"往"预测"那边拉，两边就不会一起退化成常数。
     这是 BYOL、V-JEPA 等方法的标准做法。
2. **方差护栏**：要求 z 的每一维在一个 batch 的不同图片之间至少要有一定差异（标准差 ≥ 1），否则加罚分。
   所有图片编成同一个向量，标准差就是 0，会被重罚。

### 6.4 训练数据：两种"答案"

#### A. 真实飞过的（executed）

第 1 步录数据时，每条 rollout 的动作是一段一段"保持"的（每段约 1 秒）。从中挑出满足条件的时刻 t：
**从 t 到 t+32 步，动作一直没变**（`window_valid`）。只有这样，"保持动作 a 走 k 步"的说法才成立。

对每个这样的 t，标签全部来自**真实飞过的轨迹**：

- 预测器的答案：第 t+4、t+8、t+16、t+32 帧的画面（交给目标编码器）；
- 碰撞标签：在 t 到 t+k 之间，真实离柱子的最小距离是否 < 0.7 m、是否 < 0.35 m。共 4×2 个 0/1。

局限：每一帧只告诉模型**实际执行的那一个动作**的后果。可规划器要问的是"6 个动作里哪个最好"，只学一个动作不够。

#### B. 反事实（counterfactual）

仿真器知道柱子在哪，所以可以免费算出"**如果当时做的是另一个动作**，会怎样"：从第 t 帧的位置出发，
按每个候选动作的速度画一条直线往前推 k 步，看会不会离柱子太近。这样**每一帧 × 6 个动作**都有 4×2 的危险标签。

- 这里只有碰撞标签，没有"未来画面"（因为那些动作并没有真的飞过），所以**只训练碰撞判断，不训练 z 的预测**。
- **看不见就不算**：如果造成危险的那根柱子不在相机视野内，这个标签单看画面根本回答不了，就把它的损失权重设为 0。
- **困难帧多抽**：大多数帧离柱子很远，6 个动作全是"安全"，学不到怎么比较。所以每个 batch 一半随机抽帧，
  一半专门从"有的动作危险、有的不危险"的帧里抽。

### 6.5 一个训练步：五个损失，各教什么

每一步取一个 batch（64 个样本），算 5 个损失，加在一起反向传播：

| # | 损失 | 怎么算 | 训练的网络 | 教会它什么 |
|---|---|---|---|---|
| ① | 预测损失 `pred_loss` | 实际动作下，预测的 ẑ_k 和目标编码器算的真实 z_k 的均方误差 | Encoder + Predictor | **想象未来**：给定画面和动作，未来的画面摘要是什么 |
| ② | 方差损失 `var_loss` | z 每一维在 batch 内的标准差低于 1 的部分 | Encoder | **不许偷懒**：不同画面必须编码成不同的 z |
| ③ | 实际碰撞损失 `col_loss` | 实际动作下，CollisionHeads(ẑ) 与真实距离标签的 BCE | Encoder + Predictor + CollisionHeads | **从想象的未来判断危险**（实际执行的那个动作） |
| ④ | 反事实碰撞损失 `cf_loss` | 每帧配 6 个候选动作都过一遍 Predictor + CollisionHeads，与反事实标签比 BCE（看不见的不算） | Encoder + Predictor + CollisionHeads | **比较不同动作**：同一画面下，哪个动作危险、哪个安全 |
| ⑤ | 当前危险损失 `now_loss` | DangerNowHead(z_t) 与"当前距离 < 0.7 m"的 BCE | Encoder + DangerNowHead | **反应式判断**：现在是不是已经太近 |

总损失 = ① + ② + ③ + ④ + 0.5 × ⑤。

用伪代码按顺序写出来：

```python
# ---- 第一部分：实际飞过的样本 ----
z_t   = enc(第t帧)                                  # (64, 64)   64 个样本，各 64 维
z_hat = pred(z_t, 第t帧的实际动作)                     # (64, 4, 64) 每个样本 4 个时域的预测
with no_grad:
    z_tgt = [tgt(第t+k帧) for k in (4, 8, 16, 32)]   # (64, 4, 64) 答案，由 EMA 编码器算

loss1 = mean((z_hat - z_tgt) ** 2)                 # ① 想象未来
loss2 = mean(relu(1 - z_t.std(dim=0)))             # ② 防塌缩
loss3 = BCE(cheads(z_hat), 真实碰撞标签)              # ③ 实际动作的危险判断   (64, 4, 2)

# ---- 第二部分：反事实样本（另抽一批帧：一半随机、一半困难帧） ----
z_c  = enc(这批帧)                                   # (64, 64)
z_cf = pred(z_c 每个复制 6 份, 6 个候选动作)            # (384, 4, 64)  64 帧 × 6 个动作
loss4 = BCE(cheads(z_cf), 反事实标签) × 可见性遮罩      # ④ 比较不同动作
loss5 = BCE(nhead(z_c), 当前距离 < 0.7m)             # ⑤ 现在危不危险

(loss1 + loss2 + loss3 + loss4 + 0.5*loss5).backward()
optimizer.step()                                   # Adam，学习率 1e-3，更新 enc/pred/cheads/nhead
ema_update(tgt, enc, 0.99)                         # 目标编码器慢慢跟上
```

**为什么损失 ④ 最关键**：只有 ①③ 的话，模型只见过"实际做了的那个动作"。原作者实测这样训练出来的碰撞 AUC 有 0.9，
但"往左躲还是往右躲哪个更安全"的判断和瞎猜一样。加了 ④ 之后，同一张画面配上 6 个动作、各有各的答案，
模型才真正学会"动作不同、后果不同"。

### 6.6 整体训练流程

1. 读入第 1 步生成的 `output/wm_dataset.npz`（不存在就先现场生成 32 条）。
2. **按 rollout 划分**训练集和验证集（约 80% / 20%），而不是按帧随机划分。相邻帧几乎一模一样，
   按帧划分的话验证集里的帧在训练集里有"双胞胎"，分数会虚高。
3. 一次性算好所有反事实标签和可见性遮罩，找出困难帧。
4. 训练 80 轮（epoch），每轮把训练样本打乱，按 batch = 64 执行上面的训练步。
5. 训练结束后在验证集上算指标（见下），保存模型。

**`--robust` 选项**：训练时给**在线编码器**看到的画面随机加亮度变化、噪声和模糊（第 20 课的做法），
但**目标编码器看到的画面不加**。这样答案保持稳定，编码器学会不受外观变化干扰。第 5 步用。

### 6.7 训练完怎么判断好不好

| 指标 | 含义 | 原作者结果 |
|---|---|---|
| latent MSE@32 vs no-op | 预测 667 ms 后的 z 的误差，对比"直接拿现在的 z 当预测"的误差。前者必须更小，说明预测器真的学到了东西 | 1.200 vs 2.538 |
| AUC@4/8/16/32 | 实际动作下，警戒环概率区分"会危险 / 不会危险"的能力。0.5 = 瞎猜，1.0 = 完美 | 0.96 |
| now-AUC | 当前危险头的 AUC | 0.81 |
| **veer-ranking** | **最重要**。挑出"往左躲和往右躲一个安全、一个危险，而且柱子在画面里"的关键时刻，看模型是否把真正安全的那边判为更安全。0.5 = 瞎猜 | **1.00** |
| int8 weights | 模型大小 | 81.3 KB |

前几项测的是"检测"，veer-ranking 测的是"选择"。第 4 步的规划器靠的是后者。

### 6.8 训练好之后怎么用（衔接第 4 步）

规划器每 1/12 秒做一次决定：

1. 当前画面 → Encoder → `z`（只算一次，这是最贵的部分）；
2. 把 `z` 复制 5 份，分别配上 5 个候选动作 → MultiPredictor → 5 组未来 ẑ；
3. → CollisionHeads → 5 张 4×2 的概率表；
4. 比较：如果"直飞"明显比"往旁边躲"危险，就选更安全的那一边躲。

DangerNowHead 则被第 4 步的反应式基线使用，作为对照。

其它脚本用 `load_model()` 读取，得到 `(enc, pred, cheads, nhead, meta)`。目标编码器 `tgt` 只在训练时有用，不保存。

## 7. 第 3 步 `proactive_avoid.py`：只看"决策时机"的示意实验

这是一个**完全不用神经网络、不用仿真器**的二维质点运动学演示，目的只有一个：把"提前多久做决定"这个变量单独拎出来。

- 起点 (0, 0)，终点 (3, 0)，两根柱子：(1.3, 0.10) 正挡在路上，(2.1, 0.55) 在旁边。
- 无人机是一个**加速度有上限**的质点：巡航 1.2 m/s，最大加速度 2.2 m/s²，最大速度 1.7 m/s，步长 0.05 s。
  加速度上限是关键：真无人机不能瞬间转向，反应晚了就是没有足够空间躲。
- 两个控制器只差在"什么时候开始躲"：
  - **reactive**：当前离最近柱子 < 0.6 m 时开始躲；
  - **proactive**：如果保持当前速度，**未来 0.6 s 内**会离某根柱子 < 0.6 m，就开始躲（用线段到点的最近距离算）。
- 一旦触发，期望速度 = 朝目标的巡航速度 + 1.6 m/s 的"远离最近柱子"推力，然后按加速度上限去追这个期望速度。

这里的"未来 0.6 s"用的是仿真器的**特权几何信息**（直接知道柱子位置），所以是确定性的。
在真机上，这个前瞻正是第 2 步世界模型的碰撞头从相机画面里预测出来的东西。第 4 步就把这根"拐杖"拆掉。

```bash
python src/proactive_avoid.py              # 生成 output/proactive_vs_reactive.png
python src/proactive_avoid.py --selftest   # 断言：proactive 更早触发、净空更大、不坠机
```

## 8. 第 4 步 `wm_closed_loop.py`：只靠相机的闭环飞行

这一步把世界模型真正接进控制回路。**控制回路里的危险信号只来自相机**：画面 → 编码器 → 预测器 → 碰撞头。
柱子位置只用来布置场景和事后评分（最小净空、是否坠机）。

### 8.1 常量

| 常量 | 值 | 含义 |
|---|---|---|
| `GOAL_X` | 3.0 m | 终点线 |
| `TMAX` | 360 步 | 每回合步数上限（7.5 s） |
| `DECIDE_EVERY` | 4 | 每 4 个控制步决策一次，即 **12 Hz**（对机载芯片诚实的决策频率），PID 仍是 48 Hz |
| `THETA_NOW` | 0.5 | 反应式触发阈值：P(现在太近) > 0.5 |
| `EVADE_HOLD` | 24 步 | 一旦决定躲避，保持这个动作 0.5 s 再重新判断 |
| `W_DANGER, W_HEAD, W_SWITCH, W_PROG` | 6.0, 1.0, 0.5, 1.2 | MPC 代价权重（`W_SWITCH` 在当前代码里没有用到） |
| `W_CENTER` | 1.5 | 走廊回中先验的权重 |
| `W_HORIZON` | (1.0, 0.6, 0.35, 0.2) | 4 个时域的"紧迫度"权重：近的危险算满分，远的危险只是早期预警 |
| `MARGIN_WM` | 0.4 | 相对触发门槛 |
| `SCENARIO_SEED` | 11 | 演示航道的随机种子 |

### 8.2 `WMPolicy`：基于世界模型的 tiny latent MPC

**菜单**：6 个指令去掉 `climb`，剩 5 个：`forward, slow, veer_left, veer_right, hover`。
去掉 `climb` 是因为：危险标签只看水平距离，爬升时水平速度更慢，所以"看起来更安全"，规划器会钻这个空子直接飞过航道上方，
根本没学会视觉避障（原作者追查到过这种情况）。模型本身仍然认识全部 6 个指令。

候选动作 = 菜单动作 × 当前速度倍率 / `A_NORM`。构造时预先算好每个候选的固定代价项：

- `heading`（航向误差）= 1 − vx/|v_xy|：forward/slow 为 0，两个 veer 约 0.29，hover 为 1；
- `progress`（前进量）= vx / 菜单中最大 vx：forward 1.0，slow 0.375，veer 0.625，hover 0；
- `vy`：用于预测躲避结束后的 y 坐标。

**`decide(frame, state)` 每 12 Hz 调用一次**：

1. 如果正在执行躲避（`hold > 0`），就继续执行，`hold` 减 4，直接返回。
2. 否则：**编码器只运行一次**得到 `z`，再把 `z` 复制 5 份、配上 5 个候选动作送进预测器和碰撞头，得到
   `p`，形状 (5 个候选, 4 个时域, 2 个环)。昂贵的编码器是共享的，所以在 GAP8 上把 5 个未来"想一遍"几乎不额外花钱。
3. 按紧迫度加权，把 4 个时域合成一个数：
   - `warn[i] = Σ_k p[i, k, 警戒环] × W_HORIZON[k]`（"很快会靠近"）
   - `crit[i] = Σ_k p[i, k, 临界环] × W_HORIZON[k]`（"马上要撞"）
4. **触发判断（相对触发）**：
   - `edge = warn[forward] − min(warn[veer_left], warn[veer_right])`，即"直飞比较好的那边转向危险多少"；
   - `imminent = max(p[forward, k=4 和 k=8, 临界环])`，即"直飞会不会在约 170 ms 内撞上"；
   - 如果 `edge < 0.4` **且** `imminent < 0.5`：前方并不比旁边更危险，继续 `forward`。
   - **为什么用相对门槛**：碰撞头的概率有一个随场景变化的"底噪"（空旷处的雾感、侧柱干扰），会让所有候选的概率一起上下浮动。
     固定的绝对阈值在一个航道上调好，换个航道就误触发（实测：干净航道 100% 误触发）。而"差值"只有在前方真的被挡住时才会拉开。
   - **为什么还要 `imminent` 兜底**：当无人机已经深陷危险时，所有候选的概率会一起饱和到接近 1，差值反而塌缩了，
     这时靠"直飞 170 ms 内就要撞"这个绝对条件强制躲避。
5. **选择往哪边躲**：只在两个 veer 之间比较代价，选最小的，保持 24 步：

   ```
   danger  = 0.25 × warn + 0.75 × crit          # 临界环权重大：在警戒环里时只有坏动作才"马上要撞"
   y_after = 当前 y + vy × 0.5 s                  # 用自身里程计预测躲完后的横向位置
   cost    = 6.0 × danger + 1.0 × heading + 1.5 × |y_after| − 1.2 × progress
   ```

   因为只在两个 veer 之间比，而两个 veer 的 `heading` 和 `progress` 完全相同，**实际起作用的只有 `danger` 和回中项 `|y_after|`**。
   回中项的意义：相机看不到 60° 以外的东西（侧柱就在那里），所以在其它条件差不多时，优先选择躲完后更靠近走廊中线的那边。
   它只用无人机自己的 y 坐标，从不用柱子位置。原作者实测：没有这一项时，躲避动作会偏到侧柱正好所在的位置，发生"盲侧刮擦"。

`begin(pillars)` 里直接 `del pillars`：这个策略**拿不到**柱子位置，这正是重点。

### 8.3 `ReactivePolicy`：诚实的反应式基线

- 同一个编码器，但只用 danger-now 头：P(现在 < 0.7 m) > 0.5 就躲。
- **故意给它一个优待**：触发时，用**特权的柱子位置**告诉它往哪边躲（无人机在最近柱子的左边就往左躲，反之往右）。
  真实的反应式系统需要第 17 课的深度网络才能知道方向。
- 所以它和 WMPolicy 的差别**只在时机上**。如果世界模型在自己从画面里选方向的情况下依然赢，这个胜利就是真的。

### 8.4 `run_episode(env, policy, scenario_seed, ...)`：通用的回合运行器

后面第 4b、4c、5、6 步都复用它。流程：

1. 用 `scenario_seed` 重置环境、生成柱子。**同一个种子 = 同一条航道**，所以不同策略可以飞"完全相同的考题"。
2. 每 4 步拍照并调用 `policy.decide()`；记录第一次偏离 `forward` 的步数为 `trigger`（触发时刻）。
3. 执行动作；记录轨迹和最小净空；x ≥ 3.0 就结束。

参数：

- `in_path=False`：没有正前方柱子的"干净"航道，直飞也是安全的，用来统计**误触发**（false positive）。
- `speed`：整组指令的速度倍率；`solo=True`：只有一根正前方柱子。
- `randomize=True`（第 5 步）：随机柱形/颜色、0–2 步指令延迟（用 `pending` 队列实现）、±8% 执行噪声，
  并且策略看到的每一帧都经过第 20 课的 `shift_appearance`（变暗 + 加噪声）。评分仍用真实几何。

返回：`path` 轨迹、`pillars`、`min_clear` 最小净空、`trigger`、`crashed`（min_clear < 0.22）、`steps`、`reached`（是否到达终点）。

## 9. 第 4b 步 `eval_world_model_policy.py`：多场景记分板 + 机载预算

单条演示航道可能恰好对某个控制器有利。这个脚本跑 **100 个随机种子**：每 10 个里 7 个有正前方柱子、3 个是干净航道，
两种策略飞同样的航道，报告：

| 指标 | 说明 |
|---|---|
| `crash_rate` | 有威胁航道上的坠机率 |
| `mean_min_clearance` | 平均最小净空 |
| `mean_trigger_lead` | 两者都触发的航道上，世界模型平均早触发多少毫秒 |
| `false_positive` | 干净航道上的误触发比例 |
| `goal_time` | 两者都没坠机且都到终点时，世界模型到达终点多花的时间百分比 |
| `decision latency` | 本机实测每次决策耗时，以及 GAP8 估算 |

### 9.1 机载预算 `onboard_budget()` 是怎么算的

GAP8 的 512 KB L2 内存要**同时**装下三样东西：

1. **int8 权重**：4 个网络的参数总数 = 83,241 字节 ≈ **81.3 KB**。
2. **峰值激活**：沿着编码器逐层前向，记录每层输出张量的元素数（ReLU 在设备上与卷积融合，不单独占缓冲区）：
   输入 3×64×64 = 12,288，conv1 输出 16×32×32 = 16,384，conv2 输出 8,192，conv3 输出 4,096。
   某一时刻需要同时存在的是"一层的输入 + 输出"，最大的一对是 12,288 + 16,384 = 28,672 字节 ≈ **28.0 KB**。
3. **DMA 双缓冲工作区**：再按峰值激活估一份 = **28.0 KB**。

合计 81.3 + 28.0 + 28.0 = **137.3 KB < 512 KB**。

**计算量（MACs，乘加次数）**：

- 编码器卷积：每层"输出元素数 × 输入通道数 × 卷积核面积"，三层合计约 3.59 M，再加投影层 16k；
- 每个候选动作要跑一遍预测器 + 碰撞头 + 当前头的线性层，约 42k；
- 一次决策 = 编码器 1 次 + 6 个候选 × 线性层 ≈ **3.9 M MACs**。
- 假设 GAP8 的 int8 有效吞吐为 0.5 GMAC/s（PULP-NN 级内核的量级假设，代码里明说了，可以质疑），
  一次决策约 **8 ms**，远小于 12 Hz 决策周期的 83 ms。

（注：MPC 实际只比较 5 个候选，这里按 6 个算，偏保守。）

```bash
python src/eval_world_model_policy.py --seeds 100
python src/eval_world_model_policy.py --selftest      # 10 个种子
```

### 9.2 怎么读这张记分板

这些是"杂乱航道 + 0.8 m/s 巡航"的结果。侧柱在 60–90° 方位，**物理上就在前向相机视野之外**，
躲避时如果偏到那里，就可能刮到一根从没在画面里出现过的柱子。所以没有记忆的手写规划器在这里有一个实测的坠机尾巴（原作者：16%），

## 10. 第 4c 步 `speed_sweep.py`：速度一高，反应式就撑不住

**物理推理**：

- 反应式在**固定距离**触发（danger-now 头学的是"水平距离 < 0.7 m"）。速度越快，从触发到撞上的时间越短；
  横向机动能力有限，到某个速度，躲避动作就塞不进剩下的时间了。
- 世界模型在**固定时间**触发（约 0.7 s 的前瞻，而且碰撞头是以指令速度为条件训练的），相当于一个随速度成比例增长的距离。
- 一句话：**反应是距离预算，预判是时间预算。速度消耗前者，不消耗后者。**

做法：速度倍率依次取 1.0、1.25、1.5、1.75、2.0（即 0.8 → 1.6 m/s），每个速度跑 30 条**单柱**航道（`solo=True`），
各速度用同一组种子，所以每提一档速度只改变了一件事。同一个模型（训练时覆盖了 0.6–1.6 m/s）驱动所有运行。

如果第 6 步训练出的策略文件存在（`learned`、`learned-rnn`、`learned-rnn-edge`、`learned-rnn-curr`），会**自动加入**比较。

```bash
python src/speed_sweep.py                 # 生成 output/speed_sweep.png（左：坠机率 vs 速度；右：平均净空 vs 速度）
python src/speed_sweep.py --seeds 30
python src/speed_sweep.py --selftest      # 只测 2 个速度、8 个种子
```

## 11. 第 5 步 `eval_robustness.py`：域随机化，给 sim-to-real 差距标价

到目前为止，一切都是在**和训练时一样干净的**仿真器里测的，这是经典的 sim-to-real 陷阱。
这一步在上硬件之前先"标价"：拿正式（干净训练）的模型，在它从没见过的条件下测：
随机柱形/颜色、0–2 步指令延迟、±8% 执行噪声，以及策略看到的每一帧都经过第 20 课的固定外观偏移。

报告三个数：

1. **干净数据集上的 AUC**：用种子 909 新生成 12 条干净 rollout，算 32 步时域、警戒环的 AUC。它在训练环境里管不管用？
2. **随机化数据集上的 AUC**：同样种子生成 12 条随机化 rollout，并对画面施加 `shift_appearance`，再算 AUC。差距就是要"买回来"的东西。
   同时在随机化数据上测 veer-ranking（注意：这里的 veer-ranking 用的是没加外观偏移的原始随机化画面）。
3. **随机化条件下的闭环**：AUC 只是检测器的分数，无人机实际飞的是规划器。30 条有威胁航道、全部随机化，
   比较 reactive / wm 以及（如果存在）第 6 步的 `learned`、`learned-rand`、`learned-rnn-rand` 策略的坠机率和净空。

**"Track B" 修复方案**：用随机化数据重新训练：

```bash
python src/gen_wm_dataset.py --randomize --rollouts 64   # ⚠ 会覆盖 output/wm_dataset.npz，见第 13 节
python src/train_world_model.py --robust                 # 生成 output/world_model_robust.pth
python src/eval_robustness.py --seeds 30                 # 检测到 robust 模型会多打印一行对比
```

思路是"在变化之中训练，而不是在变化旁边训练"。诚实说明：随机化只能对付**被建模了的**差距；没建模的（真实光学、真实气流）
只能靠真机实测（课程里叫 Track E）。

```bash
python src/eval_robustness.py --selftest      # 8 条验证 rollout、6 个种子；断言干净 AUC > 0.9、随机化 AUC > 0.6
```

## 12. 第 6 步 `learn_policy.py`：用强化学习把决策器学出来

第 4 步的结论是：模型的排序已经完美（veer-ranking 1.00），**瓶颈是手写的代价函数**。
原作者调了 8 种规划器配置，每次修好一个失效模式又暴露下一个，杂乱航道的 16% 坠机尾巴始终在。
这一步的做法是：**别再调代价函数了，把它学出来。**

配方就是第 19 课的 PPO，只是对准了第 29 课的世界模型。

### 12.1 观测：不是像素，也不是柱子位置，而是世界模型自己的输出

`ObsBuilder.push(frame, y, prev)` 每次决策构造一步的观测：

| 部分 | 维数 | 内容 |
|---|---|---|
| 碰撞概率 | 5 × 8 = 40 | 对菜单里每个候选动作，4 个时域 × 2 个环的碰撞概率 |
| 自身状态 | 2 | `y / 2.5`（自己的横向位置）、`速度倍率 / 2.0` |
| 上一个动作 | 5 | one-hot |
| **单步合计** | **47** | |

**记忆的两种方式**：

- **默认：堆叠记忆**。把最近 `HISTORY = 12` 次决策的观测拼起来（12 Hz 下约 1 秒），观测维数 12 × 47 = 564。
  这样一根柱子滑出 60° 视场后，它的信息还会在观测里多留一秒。
- **`--recurrent`**：用 sb3-contrib 的 `RecurrentPPO`。观测只有当前 1 步（47 维），由 LSTM 携带记忆，理论上能记得更久。
  这是全课唯一的可选新依赖。

### 12.2 环境 `WMPolicyEnv`（gymnasium 环境）

- 仿真 48 Hz，PID 用 `VelCommander`，智能体 12 Hz 决策（每个动作执行 4 个控制步）。
- 动作空间：`Discrete(5)`，即同样的 5 个指令菜单（不含 climb）。
- **每回合 `reset()`**：随机新航道（80% 有正前方柱子、20% 干净），随机速度倍率（默认 0.75–2.0 均匀抽）。
- **奖励（第 19 课原样）**：

  ```
  每步奖励 = 25 × (本步 x 前进量) − 0.02
  撞柱（距离 < 0.22 m）：−30，回合结束
  到终点（x ≥ 3.0）：   +50，回合结束
  |y| > 2.4 或决策次数达到 90 次（= 360/4）：截断
  ```

  **任何地方都没有手工调的"危险"奖励项**，这正是要点：危险如何权衡，交给学习。
- 智能体看到的一切都来自相机经过世界模型；柱子位置只用来布置场景和判断撞没撞，和 `run_episode` 一样。

### 12.3 训练变体（选项）

| 选项 | 作用 | 保存文件 |
|---|---|---|
| （默认） | 堆叠记忆 + PPO，`ent_coef=0.01`，其余为 SB3 默认超参 | `ppo_wm_policy.zip` |
| `--recurrent` | LSTM 记忆，隐藏层 64（`--lstm-size`），BPTT 窗口 256 步（`--n-steps`） | `ppo_wm_policy_recurrent.zip` |
| `--randomize` | 在第 5 步的"风暴"里训练：随机柱子、指令延迟、执行噪声，每帧做 `jitter` 外观扰动 | 文件名加 `_rand` |
| `--edge-bias` | 一半回合的速度倍率改从 1.5–2.0（1.2–1.6 m/s）抽。均匀抽样会"双重饿死"高速边缘：高速段只占区间一小截，而且高速回合结束得更快，决策次数更少 | 文件名加 `_edge` |
| `--curriculum` | 只用于 LSTM：同样的总步数分三段依次训练：自然分布 → 一半高速 → 1/4 高速混合收尾 | `ppo_wm_policy_recurrent_curr.zip` |
| `--timesteps` | 训练总步数，默认 300,000（原作者在 Mac 上约 16 分钟） | |
| `--eval` | 不训练，只做比较 | |
| `--seeds` | 比较时的航道数，默认 40 | |

注意：`WMPolicyEnv` 每次都加载 `output/world_model.pth`，所以**必须先跑完第 2 步**（这里没有自动训练小模型的兜底）。

### 12.4 `LearnedPolicy`：让学出来的策略接进同一套测试工具

它和 `WMPolicy`、`ReactivePolicy` 有相同的接口（`begin`、`decide`），所以 `run_episode`、第 4b 记分板、第 4c 速度扫描都能原样使用。
加载时根据模型的观测维度自动推断堆叠深度，根据类名判断是不是 LSTM；LSTM 版会在回合之间正确重置隐状态。

### 12.5 比较 `compare(n_seeds)`

训练结束后（或 `--eval`）自动执行：所有已存在的策略在两类航道上比较：

- **cluttered**：杂乱航道（有正前方柱子 + 侧柱），速度倍率 1.0（0.8 m/s）；
- **fast**：单柱航道，速度倍率 2.0（1.6 m/s）。

### 12.6 命令行

```bash
python src/learn_policy.py --timesteps 300000             # 堆叠记忆版
python src/learn_policy.py --recurrent                    # LSTM 版
python src/learn_policy.py --recurrent --edge-bias        # LSTM + 高速边缘过采样
python src/learn_policy.py --curriculum                   # LSTM + 三段课程
python src/learn_policy.py --randomize                    # 在风暴里训练（堆叠版）
python src/learn_policy.py --eval                         # 只比较已训练好的策略
python src/learn_policy.py --selftest                     # 检查维度并各做一次极小规模训练（只测连线，不测效果）
```

## 14. 原作者的实测结果汇总

以下数字来自原课程 README（作者在自己的机器上测得），你自己跑的结果会因随机性和平台有所不同。

**第 1 步**：64 条 rollout × 120 步，87 个保持干预片段；各时域正样本比例 0.25–0.39。

**第 2 步**：`latent MSE@32 = 1.200`（不预测时 2.538），`AUC@4/8/16/32 = 0.96`，`now-AUC = 0.81`，
`veer-ranking = 1.00 (n=25)`，int8 权重 81.3 KB。

**第 4 步**（演示航道）：反应式最小净空 0.38 m（第 60 步触发），世界模型 0.48 m（第 36 步触发），
**提前 24 步 ≈ 500 ms**，两者都没坠机。

**第 4b 步**（100 航道）：坠机率反应式 1% → 世界模型 16%（侧柱盲区尾巴，见 9.2 节）；
平均提前 **243 ms**；误触发都是 0%；到终点时间 +2%；决策延迟本机 0.4 ms、GAP8 估算约 8 ms；总预算 137.3 KB。

**第 4c 步**（单柱航道坠机率）：

| 巡航速度 | 反应式 | 世界模型（手写 MPC） | 学出的策略（堆叠记忆） | LSTM | LSTM + 高速过采样 | LSTM + 课程 |
|---|---|---|---|---|---|---|
| 0.8 m/s | 0% | 10% | **0%** | 0% | 0% | 7% |
| 1.0 m/s | 0% | 0% | **0%** | 0% | 0% | 23% |
| 1.2 m/s | 3% | 0% | **0%** | 0% | 0% | 13% |
| 1.4 m/s | **40%** | 0% | **0%** | 3% | 0% | 47% |
| 1.6 m/s | **60%** | 10% | **0%** | **40%** | 3% | **73%** |

**第 5 步**：干净 AUC 0.96 → 随机化 + 陌生相机 AUC 0.82；用 `--randomize` + `--robust` 重训后回升到 0.92。
但更好的检测器配手写规划器反而飞得更差（坠机 17% → 30%），因为规划器的门槛是按原模型的概率底噪校准的。
教训：**分数更好不等于飞得更好。**学出来的堆叠记忆策略在风暴里坠机 10%，追平了拿特权方向的反应式基线。

**第 6 步**（60 条杂乱航道 @ 0.8 m/s）：反应式 2%、手写 MPC 17%、**学出的堆叠记忆策略 0%**；
单柱 @ 1.6 m/s：反应式 70%、手写 MPC 8%、**学出的策略 0%**。底下是**同一个**世界模型，只是"做决定的东西"换成了学出来的。

关于几种记忆变体的结论：LSTM 在高速边缘不稳定；`--edge-bias` 补上了高速边缘，但把杂乱航道的坠机率从 2% 推高到 10%；
`--curriculum` 反而处处更差。on-policy 学习"没有昨天"，每段只对着自己的数据分布优化，会覆盖上一段学到的东西。
**最简单的堆叠记忆至今没在任何地方输过。**

## 15. 术语表

| 术语 | 含义 |
|---|---|
| rollout | 一次从起点开始的完整飞行试验 |
| 控制步 / step | 48 Hz 的一个控制周期，约 20.8 ms |
| 时域 / horizon `k` | 向前预测多少个控制步：4/8/16/32 |
| 保持片段 held segment | 同一个指令连续保持约 1 秒的一段飞行 |
| 反事实 counterfactual | "如果当时做的是另一个动作会怎样"，由仿真器几何免费算出 |
| 特权信息 privileged | 只有仿真器才知道的信息（如柱子真实位置），只能用于标签和评分，不能用于控制 |
| 警戒环 / 临界环 | 0.7 m / 0.35 m 的水平距离阈值 |
| 净空 clearance | 到最近柱子的水平距离；最小净空 < 0.22 m 即坠机 |
| 触发 trigger | 第一次从直飞切换到躲避的时刻 |
| 反应式 reactive | 根据"现在多近"做决定 |
| 预判式 proactive | 根据"预测未来会多近"提前做决定 |
| MPC | 模型预测控制：对每个候选动作预测后果，选代价最小的 |
| 塌缩 collapse | 编码器把所有输入编码成同一个向量的退化解 |
| EMA 目标编码器 | 在线编码器的缓慢滑动平均副本，用来产生预测目标 |
| veer-ranking | 在关键帧上，模型能否把真正更安全的转向方向排在前面 |
| FOV | 视场角，本课相机 60° |
| GAP8 / AI-deck | Crazyflie 的 AI 扩展板及其芯片，L2 内存 512 KB |
| int8 量化 | 把权重压成 8 位整数，每个参数 1 字节 |
| MAC | 一次乘加运算，衡量计算量 |
| 域随机化 DR | 训练时故意加入随机变化，提高对未见条件的鲁棒性 |
| sim-to-real | 从仿真迁移到真机时的性能差距 |
| PPO / RecurrentPPO | 强化学习算法 / 带 LSTM 记忆的版本 |
